# Project path: proposal, midpoint, final

This page follows your own project from the first plan to the final presentation. It replaces two earlier pages, a proposal page and a final page.

The required work is in [minimum path](minimum-path.md). This page only says when each part appears and what to show. It does not require one agent architecture. A student who works with Hermes, Cursor, a local script, a visual tool, or no AI can use it.

## The path

| Stage | Session | What you bring | Notes you keep |
|---|---|---|---|
| Proposal (semester plan) | [04 project presentations and plans](../SESSIONS/04-project-presentations-and-plans.md) | The project, and how the agent setup enters it | Draft [provenance](provenance.md) |
| Midpoint | [04 project presentations and plans](../SESSIONS/04-project-presentations-and-plans.md) | The system as it stands, even if rough | [Verification](verification.md) plan, lint entry if you have one |

## Proposal

Write one page for Session 04. Cover these points.

1. **Project.** What you make, and why it matters to your practice. At best this work is part of your own art project.
2. **Where the agent enters.** How *agent as interface* appears in the project. "AI will generate my visuals" is not enough.
3. **The system.** Name the seven parts from [minimum path](minimum-path.md): knowledge store, access boundary, model endpoint, tool set, verification method, provenance, critical reflection. A small choice is enough for each.
4. **No AI.** If you do not want to use AI, present your research or your investigative plan instead. That is a valid position.

Session 04 time per person is about 5 to 8 minutes with feedback.

## Midpoint

Show the setup as it stands:

- the folder or vault layout, and the access boundary
- the model, the harness, and the tools
- a first draft of the provenance note
- one risk and one question that you want peers to answer

## Final

The final presentation in Session 08 has five parts. It is not a polished exhibition by default.

1. **Architecture.** A diagram or a live walkthrough of the system.
2. **Use.** One artistic or research scenario where the setup matters.
3. **Critical reflection.** What the system did to the work. See [reflection](reflection.md).
4. **Provenance note.** Which model, which tools, who decided, where it ran. See [provenance](provenance.md).
5. **Open question** that you still hold.

Students who chose research instead of AI use present their investigation.
