# Interface score

*Scaffold for Session 06 and later.* Use it when you reach [06 agent as interface](../SESSIONS/06-agent-as-interface.md). It is not a week-1 task, and it is not part of the required [minimum path](minimum-path.md). It is a useful way to check your own system.

An interface score is one page that says how your agent meets you and your work. Write what you intend, then compare it with what the system really does.

| Part | Your answer |
|---|---|
| Roles. What the agent does, and what you do | |
| Tools. What it can call. List the real tools | |
| Memory. What it keeps, where, and for how long | |
| Taboos. What it may not read, write, or decide | |
| Human-only pages. Where your own voice lives | |
| Kill switch. How you stop it, and when you should | |
| When AI is unnecessary. A short checklist | |

## Check the score against the system

Pair critique, as in Session 06: does the score match what the setup does? Check it against the real `SCHEMA.md` and the real tool list, not against the intention.

Move the taboos into the schema. Human-only paths and "must ask first" tools belong in `SCHEMA.md`. See [llm wiki standard files](../PRACTICE/02-knowledge-bases/llm-wiki-standard-files.md) and [starter knowledge base](../PRACTICE/02-knowledge-bases/starter-knowledge-base.md).
