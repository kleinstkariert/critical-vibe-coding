# Minimum path

This page states the work that is required.
The technical object of the course is a **student-designed agentic production system**.
That system is the set of choices that lets an agent do one piece of your work.
You design it. You choose the tools.
No purchase is required.
Alternatives are allowed.

Hermes is one *reference implementation* of that system.
The lecturer will install Hermes with the class.
That install is a *demonstration*.
It is *not required for assessment*.
Claude Code, Cursor, OpenCode, a local script, or another agent are valid systems. Compare them in the [tool comparison](../../research/software&DataManagement/vibe-coding-tools-and-agent-environments.md).
You do not need Hermes, Obsidian, phone sync, a local model, MCP, Discord, or a bridge to another application.
Blank forms for the required documents are in [templates](../templates/README.md).

## Required: personal manifesto

A personal manifesto is a short text, in your own words, on how you want to use AI in your practice.
It names no required product.
You develop it through the course.
You hand it in at the end.
Session 01 introduces it. It is not a week-1 deliverable.
The manifesto is required, together with the system below and the input presentations.

## Required: the system

Name these parts. A small choice is enough.

1. **Knowledge store.** Where the work lives. A folder of plain Markdown is enough.
2. **Access boundary.** What the agent may read and change, and what it may not.
3. **Model endpoint.** The model you call. It can be in the cloud or on your own computer.
4. **Tool set.** The tools the agent may use. One folder can be the whole tool set.
5. **Verification method.** How you check that the result is right.
6. **Provenance.** A record of the task, the model, the tools, and the outcome.
7. **Critical reflection.** One short text on what the system did to the work.

Do one useful task with this system.
Present the architecture and one use.
At best, this work is part of your own art project.

## Required: input presentations

You also give one input presentation with your group.
The topics and the sessions are in the [course rhythm](../SESSIONS/overview/course-rhythm.md).
One group presents in sessions 2, 3, 5, 6, and 7.

The presentations in sessions 4 and 8 use the system above.
Session 4 shows the work as it stands.
Session 8 presents the architecture, one use, and the critical reflection.

## How to read the other pages

| Label | What it means |
|---|---|
| *reference implementation* | One worked example of the system. Hermes pages use this label. You do not have to copy that example. |
| *optional extension* | A further tool or habit. You can skip it and still complete the course. |
| *advanced path* | A harder setup, such as a local model, a coding harness, or MCP. |
| *demonstration* | One example the class may watch. The Hermes install in class is this. |
| *research topic* | Reading and discussion. It is not an install task. |
| *not required for assessment* | It does not decide whether you pass. |

Hermes-specific instructions in this repository are an *optional extension* and a *reference implementation*.
The seminars still discuss political economy, labour, ecology, bias and feminism, authorship, privacy, and critique.
Use those themes in the manifesto, in the input presentation, and in the critical reflection.
They are not a list of software to install.
